# Project review — 26 November 2026

Reviewed at commit `77f063c` (213 commits, clean tree). Analysis only: no code, doc or config
was changed; this file is the only one written. Scripts, logs, the local build and the scratch
database used for the measurements live outside the repository.

## Summary

1. **Verdict: not ready to open to strangers.** The engineering base is sound (every suite green,
   core 95 % covered, no secret in the repo or its history), but the launch surface is not.
2. Blockers are legal (no published policy, age rule undecided), accounts (no email confirmation,
   no CAPTCHA, no password recovery), abuse (no rate limit, a script can fill the database) and
   duel integrity (a crafted request escapes any loss).
3. Competitive integrity is weaker than the plan's pillar 4 claims: duel content and answers are
   known to the client before play, times are self-declared, and solo levels only ever go up for a
   player who quits bad games.
4. The free plans break early: the main leaderboard takes 11 s at 10,000 players, and stored
   sessions reach the free database size in about two weeks at 1,000 daily players (estimate).
5. Question quality is uneven at low Advanced tiers (5 distinct root questions for ten levels), and
   several Method explanations are true but useless or use the wrong base.

**Strengths, briefly.** The pure core is really pure (imports only `dart:math` and `dart:async`),
generation is deterministic and pinned on VM and JavaScript including a realistic 13-digit seed,
every table has row-level security with no direct API grant except `profiles`, every
`security definer` function sets `search_path`, the level formula matches `doc/levels.md` section 3
exactly, and Get the count is solvable and in band on every round I checked (1,530 rounds).
